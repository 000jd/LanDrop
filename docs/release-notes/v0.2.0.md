# LanDrop v0.2.0

Send any file, folder, text or link to the device next to you — straight over
your Wi-Fi, with no cloud and no accounts. v0.2.0 adds persistent history,
encrypted payloads, zipped browser share links and background receiving on
Android.

## Install with one command (Linux & macOS)

```bash
curl -fsSL https://raw.githubusercontent.com/000jd/LanDrop/main/install/install.sh | bash
```

The installer detects your OS/CPU, downloads the matching asset plus
`SHA256SUMS.txt`, verifies the checksum, and installs `~/.local/bin/landrop`
(and the desktop app in a graphical session). Force the desktop app with
`--desktop`. Uninstall with:

```bash
curl -fsSL https://raw.githubusercontent.com/000jd/LanDrop/main/install/install.sh | bash -s -- --uninstall
```

## Highlights

- **Encrypted payloads and cryptographic SAS PINs** — every file send negotiates
  a fresh ephemeral X25519 session and encrypts upload chunks with RFC 8439
  ChaCha20 at their plaintext byte offset. The offset-aware keystream keeps
  encryption compatible with resumable uploads, and the PIN is derived from the
  raw shared secret, so a man-in-the-middle on the Wi-Fi sees mismatched PINs.
  Peers that do not advertise `dh_pub` keep the v0.1.0 unencrypted path.
- **Persistent history** — completed, failed, cancelled and rejected transfers,
  plus received text snippets, are stored atomically in `<config dir>/history.json`
  (mode 0600, newest 100) and restored after a restart. **Clear history** removes
  the file without touching saved files.
- **Multi-file and folder `.zip` share links** — `POST /api/share-link` now
  accepts any number of files (with relative folder paths) and bundles a
  selection or folder into an uncompressed `.zip` behind one 15-minute
  `/d/{token}` link. `POST /api/share-link-path` does the same for machine-local
  paths, and a single file is still staged directly.
- **Guest mode** — `GET /api/info` reports `is_local`; a phone or another laptop
  opening the LAN UI gets the host-only settings controls disabled with an
  explanation instead of hitting `403`s. Sending, accepting and rejecting still
  work remotely.
- **Paste button** — the Send card can read the clipboard straight into the
  snippet box, with a friendly fallback when the browser blocks access.
- **systemd user service** — `make install-service` installs the CLI plus
  `landrop.service` (`--hidden`, `Restart=on-failure`) under the user unit
  directory; `make uninstall-service` removes it.
- **Android foreground service** — a low-importance `dataSync` service with a
  quiet ongoing notification keeps the node reachable when the app is
  backgrounded or the screen is off.
- The earlier feature set is unchanged: discovery, batches and multi-device
  sends, resumable uploads, QR codes, trusted peers, speed/ETA, folder sends,
  the Android share sheet, and the quiet light/dark UI.

## Upgrade notes

- v0.2.0 stays wire-compatible with v0.1.0: an old peer sends no `dh_pub` and
  simply keeps the unencrypted transfer path. A new sender also works against an
  old receiver.
- Payload encryption covers file bytes. Offer metadata (filenames, device names,
  notes), text snippets and the upload token still travel over plain HTTP; the
  cipher is a payload layer, not a replacement for the accept prompt.
- `history.json` starts empty on the first v0.2.0 run; the previous in-memory
  history was not persisted.
- A release `.zip` uses ZIP `Stored` (no compression), so a single share-link
  archive follows the classic 4 GiB non-ZIP64 limit.
